# 场景：技术方案（参数清单）

**问题**：CAN 报文解析与私有协议逆向实施要点

---

以下清单可直接粘贴至技术方案书“CAN 报文解析与私有协议逆向实施要点”章节。

## 一、参数清单

### 1. 协议通用性与边界
1. 底层通用性：完全通用；包括帧格式、ID 优先级仲裁、错误检测、应答机制，全球统一。（一、先回答核心问题：CAN 通用吗？）
2. 上层通用性：完全不通用；8 个字节中每个字节代表什么由厂商自定义。（一、先回答核心问题：CAN 通用吗？）
3. 底层标准：ISO 11898 国际标准。（一、先回答核心问题：CAN 通用吗？）
4. 公开上层协议：J1939 有标准 PGN 表；CANopen 公开；UDS（ISO 15765）公开。（一、先回答核心问题：CAN 通用吗？）
5. 私有协议公开性：储能/BMS 绝大多数使用私有协议，基本不公开。（一、先回答核心问题：CAN 通用吗？）
6. CAN 设备通信能力：任何 CAN 设备接到总线上都能通信；但不能自动看懂对方数据。（一、先回答核心问题：CAN 通用吗？）
7. 人员能力目标：现场报文看懂比例至少 80%。（引言）

### 2. 帧结构与 ID
8. 上层数据含义描述对象：8 个字节；CAN 帧数据场长度范围：0~8 字节。（一、先回答核心问题：CAN 通用吗？；二、一条 CAN 帧长什么样）
9. 工程师解析关注块数：3 块，即 ID、DLC、数据场。（二、一条 CAN 帧长什么样）
10. 标准帧 ID：11 位；范围 0x000~0x7FF；常见于私有协议、简单系统。（📍 第一块：ID（标识符）③）
11. 扩展帧 ID：29 位；最大 0x1FFFFFFF；常见于 J1939、需要更多信息场景。（📍 第一块：ID（标识符）③）
12. ID 优先级：ID 数值越小越优先；线与机制下显性位覆盖隐性位，输者自动退让重发且不丢数据。（📍 第一块：ID（标识符）①）
13. 总线属性：广播总线；一条报文所有节点都能收到，各节点自行判断该 ID 是否与自己相关。（📍 第一块：ID（标识符）②）

### 3. DLC 与数据场
14. DLC 示例：DLC=2 时有效数据为 2 字节；若数据场写了 8 字节，后 6 字节为填充值；填充值常见 0 或 0xAA。（📍 第二块：DLC（数据长度码））
15. 数据场原始字节示例：03 1A；在 A 厂协议中表示电压 665.9V，在 B 厂协议中表示故障码 26。（📍 第三块：数据场（0~8 字节））
16. 字节序读法：小端（Intel）读 03 1A = 0x1A03 = 6659；大端（Motorola）读 03 1A = 0x031A = 794；两者差异达 8 倍以上。（坑 1：字节序（大端 vs 小端））
17. 设备字节序分布：多数 BMS 使用小端；部分工业设备使用大端。（坑 1：字节序（大端 vs 小端））

### 4. 物理量换算与 DBC
18. 物理量换算公式：物理量 = 原始值 × 分辨率 + 偏移量。（坑 2：物理量需要“换算公式”）
19. 电压换算示例：原始值 6659；分辨率 0.1 V/bit；偏移量 0；结果 665.9V。（坑 2：物理量需要“换算公式”）
20. 温度换算示例：原始值 109；分辨率 0.1 ℃/bit；偏移量 -40；结果 -29.1℃。（坑 2：物理量需要“换算公式”）
21. 换算参数来源：起始位、分辨率、偏移量需从 DBC/协议定义获取；原始报文看不出这些参数。（坑 2：物理量需要“换算公式”；关键概念：DBC 文件）
22. DBC 映射示例：ID 0x18F00400 → 字节 0-1 小端 = 电池组总压，分辨率 0.01V/bit；字节 3 = SOC，分辨率 1%/bit；字节 4 bit0-2 = 状态位，0=待机，1=充电，2=放电。（关键概念：DBC 文件）

### 5. 私有协议逆向流程参数
23. 找规律：关注同一 ID 是否周期性出现；示例周期 100ms；数据上报/状态帧通常周期性出现，事件/故障帧偶尔、不规律出现。（第一步：找规律）
24. 变工况：充电时观察哪些字节数值上升；放电时观察哪些字节数值下降；拉高温度寻找缓慢变化字节；能随工况变化的字节位置即为信号所在位置。（第二步：变工况，看谁在变）
25. 反推与验证：无文档时通过抓包、试、验证反推协议；解析内容必须获取协议文档。（六、给新人的三句话总结；关键概念：DBC 文件 - 行业现实）

## 二、约束/风险清单

1. 上层协议不通用，不能仅凭 CAN 底层协议解析业务语义。原因：CAN 只统一“怎么传”，8 个字节中每个字节含义由厂商定义，私有协议基本不公开。应对：必须获取协议文档/DBC，或开展反推验证。（一、先回答核心问题：CAN 通用吗？；六、给新人的三句话总结）
2. 私有协议无文档导致进度风险。原因：绝大多数储能/BMS 使用私有协议，基本不公开，反推耗时。应对：预留抓包、变工况、试错与验证周期。（一、先回答核心问题：CAN 通用吗？；关键概念：DBC 文件 - 行业现实）
3. DBC 缺失或错误风险。原因：DBC 是“翻译字典”，起始位、分辨率、偏移量写在 DBC 中，原始报文看不出。应对：多源获取，交叉验证信号定义。（坑 2：物理量需要“换算公式”；关键概念：DBC 文件）
4. 字节序误判风险。原因：同一 03 1A 小端读为 6659，大端读为 794，差异达 8 倍以上；多数 BMS 小端，部分工业设备大端。应对：用已知物理量或变工况验证字节序。（坑 1：字节序（大端 vs 小端））
5. 物理量换算错误风险。原因：原始值必须按“物理量 = 原始值 × 分辨率 + 偏移量”换算；偏移量可为 -40，有偏移时结果可能为负。应对：在方案中固化公式、单位与量程校验。（坑 2：物理量需要“换算公式”）
6. DLC 与填充值误判风险。原因：DLC=2 时仅前 2 字节有效，后 6 字节可能是 0 或 0xAA 填充，不是有效数据。应对：严格按 DLC 截取有效字节。（📍 第二块：DLC（数据长度码））
7. ID 语义误判风险。原因：CAN ID 不是设备地址，而是消息标签和优先级；CAN 是广播总线，所有节点都能收到。应对：按协议表做 ID 映射，不能按设备地址解析。（📍 第一块：ID（标识符）②；六、给新人的三句话总结）
8. 标准帧/扩展帧混淆风险。原因：标准帧 11 位，范围 0x000~0x7FF；扩展帧 29 位，最大 0x1FFFFFFF；适用协议不同。应对：解析前先确认帧格式。（📍 第一块：ID（标识符）③）
9. 事件/故障帧漏判或误判风险。原因：事件帧、故障帧偶尔且不规律出现，非周期上报；只看周期帧易漏关键状态。应对：先区分周期帧与事件帧，再分别解析。（第一步：找规律）
10. 反推结论未经验证风险。原因：信号映射需通过充电、放电、拉高温度等变工况确认，并经过抓包、试、验证。应对：将变工况验证列为逆向验收条件。（第二步：变工况，看谁在变；六、给新人的三句话总结）
11. ID 优先级影响发送时序。原因：ID 数值越小优先级越高；多节点同时发送时输者自动退让重发，虽不丢数据但高优先级先发。应对：解析与测试时记录 ID 优先级影响。（📍 第一块：ID（标识符）①）
